# Lookup eval — 50 queries, 4 adapters (2026-05-13)

Benchmark of codemap against three baselines — ripgrep, Aider's repomap, and
dense embeddings (Sentence-Transformers `all-MiniLM-L6-v2`) — on 50 hand-curated
natural-language lookup questions across four open-source repos
(3 TypeScript + 1 Python).

## Methodology

### Query design

50 natural-language questions of the form *"where is X?"* / *"how does Y work?"*
were written by hand against four upstream repos:

| Repo | Lang | # queries |
|------|------|-----------|
| `inngest/inngest-js` | TypeScript | 10 |
| `excalidraw/excalidraw` | TypeScript | 10 |
| `TanStack/query` | TypeScript | 15 |
| `tiangolo/fastapi` | Python | 15 |
| **Total** | | **50** |

The query set targets structural lookups an engineer or coding agent would ask
when entering an unfamiliar codebase: where a class lives, where a hook is
implemented, where a particular middleware/feature is wired up. Queries are not
overlapping; each names one or two specific files as ground truth.

### Ground truth

For each question, the expected file(s) were identified via plain `find` and
`grep` exploration of the upstream repo — **not** via codemap itself, to avoid
circular bias. Truth files are stored as JSONL in `eval/data/lookup-truth-*.jsonl`,
one record per line:

```json
{"title": "where is the FastAPI application class?", "files_changed": ["fastapi/applications.py"]}
```

### Adapters

All four adapters are run from a clean checkout via `eval/scripts/run-lookup.ts`
on the same `/tmp/eval-*` clones produced by `setup-test-repos.sh`.

| Adapter | Mechanism |
|---------|-----------|
| **codemap** | Tree-sitter AST graph + keyword scoring + PageRank (this repo) |
| **embedding** | `Xenova/all-MiniLM-L6-v2` via Transformers.js; one chunk per file (first 4096 chars), cosine ranked, file embeddings cached per repo |
| **grep** | Ripgrep with codemap's `tokenize()` stopword filter; path-hit boost |
| **aider-full** | `aider --show-repo-map` PageRank-ordered file list returned in full (no per-query re-ranking) |

The embedding adapter caches per-repo file embeddings so the cost is
`O(files + queries)` rather than `O(files × queries)`. To keep MiniLM runs
tractable on large monorepos, each repo is capped at the first 800 source
files encountered during a deterministic walk (skipping `node_modules`,
`dist`, `tests`, `docs`, etc.).

### Metrics

For each adapter × query we compute Precision, Recall, and F1 at K=5
(except `aider-full`, which is graded over its full file list — Aider's own
default for a coding agent is to dump the entire PageRank-ordered repomap,
so we score it under that contract). Aggregations are arithmetic means across
all 50 queries.

A "hit" is any query for which F1 > 0 (i.e. at least one truth file appears
in the adapter's predictions).

## Aggregated results (50 queries)

| Adapter | F1@5 | Recall | Hits | Avg tokens |
|---------|------|--------|------|-----------:|
| **codemap** | **0.328** | **83.3%** | **45/50** | 3,318 |
| embedding (MiniLM-L6-v2) | 0.166 | 44.0% | 24/50 | 2,500 |
| grep (ripgrep) | 0.055 | 13.3% | 8/50 | 7 |
| aider-full (4096-token map) | 0.022 | 41.0% | 23/50 | 7,657 |

codemap is ~2× the F1 of the next-best baseline, finds at least one truth
file in 90% of queries (vs 48% for embeddings, 46% for aider, 16% for grep),
and uses 57% fewer tokens than the full Aider repomap.

## Per-repo F1@5

| Repo | Lang | codemap | embedding | aider | grep |
|------|------|--------:|----------:|------:|-----:|
| tanstack/query | TS | **0.359** | 0.041 | 0.023 | 0.000 |
| excalidraw/excalidraw | TS | **0.319** | 0.190 | 0.004 | 0.029 |
| tiangolo/fastapi | Python | **0.319** | 0.257 | 0.037 | 0.067 |
| inngest/inngest-js | TS | **0.302** | 0.190 | 0.017 | 0.145 |

codemap leads on every repo. The gap to embeddings is largest on
`tanstack/query` (9× F1), where the monorepo's deep package layout
(`packages/query-core/src/...`) seems to confuse one-chunk-per-file
MiniLM. The smallest gap is on FastAPI, where Python files are small,
single-purpose, and embed well at 4096 chars.

## Token efficiency

F1 per 1k output tokens (higher = better signal per token of agent context
spent):

| Adapter | F1@5 | Avg tokens | F1 per 1k tokens |
|---------|-----:|-----------:|-----------------:|
| **grep** | 0.055 | 7 | **7.857** |
| codemap | 0.328 | 3,318 | 0.099 |
| embedding | 0.166 | 2,500 | 0.066 |
| aider-full | 0.022 | 7,657 | 0.003 |

Grep "wins" this column only because its output is essentially a token-free
ranked path list — but it loses 84% of queries outright (hit rate 16%) so the
ratio is misleading on its own. Among adapters that actually answer most
queries, codemap is ~50% more token-efficient than embeddings and ~33×
more efficient than Aider's full repomap.

## Caveats

- **Hand-curated query set, single annotator.** 50 questions written by one
  engineer; no inter-annotator agreement check. Truth files are what *I* would
  expect an agent to read first, not a consensus answer. A query like
  *"where is the test client?"* assumes the test client lives in one canonical
  spot (`fastapi/testclient.py`) — an annotator who counts the integration
  helpers in `tests/` would score adapters differently.
- **Embedding model is MiniLM, not e5-large.** `Xenova/all-MiniLM-L6-v2`
  (384-dim, quantized) is ~30× smaller than `multilingual-e5-large` and was
  picked so the full eval finishes in a reasonable wall-clock time on a
  laptop. A bigger model would likely close some of the gap to codemap on
  fuzzy/conceptual queries.
- **File cap of 800 source files per repo.** Large monorepos
  (tanstack/query, excalidraw) are walked deterministically and the first 800
  matching `.ts`/`.tsx`/`.py`/etc. files are embedded. Truth files always
  fall inside the cap for the queries in this dataset, but the cap means the
  embedding adapter sees a partial picture for repos > 800 source files. The
  walk order skips `node_modules`, `dist`, `tests`, `docs`, `__pycache__`,
  and similar generated/non-source directories.
- **Aider-full is graded over its entire output, not @5.** Aider's repomap is
  designed to be consumed whole as agent context, so we let it compete on
  full recall but charge it the full token cost (avg 7,657 tokens). Truncating
  to top-5 would zero its recall on most queries since its first 5 files are
  typically `README`/`index`-style entry points.
- **One chunk per file in the embedding adapter.** This harness uses the first
  4096 chars of each file as a single chunk (matching the cached version that
  produced these numbers). The reusable `eval/adapters/embedding.ts` adapter
  in this repo chunks files at 1024 tokens — re-running with multi-chunk
  embeddings would change the embedding numbers.
- **Numbers are from a single run on 2026-05-13.** Codemap is deterministic
  given the same checkout, but Aider's repomap output can shift run-to-run as
  upstream repos move (`setup-test-repos.sh` does `--depth 1` shallow clones
  of `HEAD`). To reproduce the exact numbers in this writeup, pin the four
  repos to the commits listed in the run log committed alongside this file.

## Reproducing

```bash
bash eval/scripts/setup-test-repos.sh        # clone the 4 repos to /tmp
pip install aider-chat                       # only needed for aider-full
bun run eval/scripts/run-lookup.ts           # run the eval; ~5 min on a laptop
```

The harness prints aggregated and per-repo tables to stdout. The MiniLM model
downloads on first run (~25 MB) and is cached by Transformers.js.
